# sherpa ORT export patch — one symbol, so the voice converter can run

Adds `_OrtGetApiBase` to sherpa's exported-symbols list on Apple platforms.

## Why

The voice converter (`lib/swayco/speech/ort_runtime.dart`) drives the ONNX
Runtime **the app already ships** — sherpa links one, and a second copy makes the
iOS link fail on duplicate symbols. It therefore does not vendor a runtime; it
calls `DynamicLibrary.process()` and looks up a single symbol.

On iOS that lookup failed:

    Bad state: no ONNX Runtime in this process

ORT *is* inside `sherpa_onnx.framework` — `strings` finds `onnxruntime::…`
throughout — but none of it is reachable. Two things hide it, and neither is the
one `docs/voice-cloning.md` originally blamed:

1. `sherpa-onnx/c-api/CMakeLists.txt:21` links the dylib with
   `-Wl,-exported_symbols_list,sherpa-onnx-symbols-c.exp`. That list is
   generated by `c-api/generate.sh`, which greps for `^_Sherpa` — so **only**
   `_Sherpa*` is exported and every ORT symbol is dropped.
2. `build-ios-shared.sh` finishes with `strip -x`, removing what local symbols
   remained.

`SHERPA_ONNXRUNTIME_LIB_DIR` was a red herring: `build-ios-shared.sh` already
sets it (line 44), pointing at the *static* ORT xcframework — its own header
says "We still use static libraries for onnxruntime". Setting it changes
nothing about visibility.

## Why one symbol is enough

The ORT C API is a struct of function pointers reached through a single entry
point: `OrtGetApiBase()->GetApi(version)`. `ort_runtime.dart` looks up
`OrtGetApiBase` and nothing else — every other call goes through the struct. So
exporting that one symbol restores the whole API, with no second runtime, no
extra vendored framework, and no podspec change.

`strip -x` strips *local* symbols only, so the newly exported global survives it.

## Applying

`../sherpa_onnx_ios_patched/setup.sh` applies this after the ja and whisper
patches. It is a separate patch so the three stay independently revertible; it
touches the top of the `.exp` file while the ja patch touches ~line 115, so they
do not conflict.

Android uses a version-script (`sherpa-onnx-symbols-c.lds`) instead and is not
covered here — it does not need to be: the Android build ships ORT as a real
shared `libonnxruntime.so`, which `ort_runtime.dart` opens by name.
